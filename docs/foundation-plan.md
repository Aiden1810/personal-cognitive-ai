# 最小项目骨架实施记录

目标：落实已批准的 README / AGENTS 契约，提供能启动的三个页面、公共类型和统一数据入口，供姚与曹接续开发。

执行方式：安的 Codex 在当前工作区的 `feat/project-foundation` 分支逐步实施。此次只做骨架，不创建另一份工作区、不实现 LLM/登录/数据库。

## 结构与步骤

- [x] 根配置：Next.js、React、TypeScript、ESLint；npm 与单一 package-lock.json。
- [x] 类型：`src/types/domain.ts` 与 `api.ts` 对应 AGENTS 的 v0.1 契约。
- [x] 数据：`src/lib/data` 统一保存/读取；Node 内置测试验证保存、损坏数据、引用与状态联动。
- [x] 页面：共享布局和 `/history`、`/goals`、`/decision`，feature 目录留出模块接续入口。
- [x] 文档：实际运行步骤、数据入口使用说明和姚/曹下一任务。
- [x] 验证：测试、类型、lint、生产构建和浏览器路由/刷新验证。

交付方式：提交、推送功能分支并创建 PR，不自动合并。

## 已执行验证

- 10 个数据入口测试通过；typecheck、lint 和生产 build 通过。
- Playwright 浏览器实际打开三个页面，保存后刷新仍读取到 2 条示例记录。
- 390px 宽度决策页无横向溢出；浏览器 console 无错误或警告。
- 截图与浏览器测试日志在忽略目录中，不进入代码提交。
- ESLint 10 与 Next.js 所带 React 插件冲突，已退回 peer 范围内的 9.39.5；停止支持提示及后续升级要求见 README。

## 验收关注

- 合成占位数据和未接入 AI 清楚标识，不固定用户拒绝的具体场景。
- 读取坏数据和保存失败可见，不静默重置。
- 驳回/修改模式或删除证据时，关联目标与证据状态保持一致。
- 页面只从统一数据入口取得数据，无数据库或网络模型调用。
- 移动宽度和键盘操作基本可用，开发命令适用于 Windows。
