# 知衡：项目背景、比赛要求与 AI 快速交接

更新日期：2026 年 10 月 11 日。供新协作者或其他 AI 快速了解项目，也可整份复制到新对话。本文依据现有项目文档、代码入口及安提供的比赛邀请函整理；本轮只整理文档，没有重新验收模型、账户或全部软件功能。

## 先看这段

**知衡（Zhiheng / Personal Cognitive AI）是澳门城市大学学生为参加 2026 年第十一届「粤港澳大湾区 IT 应用系统开发大赛」澳门区分赛而开发的个人 AI 原型。**它以聊天为入口，从用户原话提出有来源的画像候选，经用户核对后形成当前画像；用户独立设定希望保持或改变的方向，后续聊天参考相关已确认画像与启用目标提供帮助。

项目的核心是「聊天 → 有依据的候选 → 用户审核 → 当前画像 → 用户目标 → 后续帮助」。七维是既有资料组织框架；AI 候选、当前状态和用户目标要分开。项目关注用户能否看见并纠正 AI 对自己的理解，以及建议能否考虑个人背景和自主目标，相关长期效果仍需验证。

团队成员只称安、姚、曹。当前由安负责全部开发、UI、比赛 PPT、讲稿和 Demo，姚、曹的新任务暂停，保留既有贡献。主要开发者是计算机科学专业低年级本科生，需要清晰、可维护、能逐步验证的实现和初学者能理解的说明。

这是 Next.js、React、TypeScript Web 项目，主要业务资料保存在浏览器；真实模型调用经过服务端，可选云端入口使用 Supabase。当前用于本地原型与演示，公开生产环境 AI 接口仍关闭。工作区名 `second me` 不代表已接入 Second Me 平台或训练个人数字分身。

比赛邀请函要求项目简报 PPT **10–15 页**，介绍视频 **2–5 分钟、可选**；澳门分赛为 **2026 年 10 月 24 日 10:00–13:00**，决赛形式为简报加答问。邀请函原定报名及首次作品提交截止为 **10 月 1 日**；安另外确认同一份比赛 PPT 可在 **15 日前更新并提交，15 日后不能再改，24 日使用最终版**。这两个时间点来源不同，不能把后者写成邀请函公布的报名延期。

## 为什么做这个项目

项目希望回答一个具体问题：用户谈过自己的经历和困扰之后，怎样让后续 AI 建议继续参考有关背景，同时让用户知道系统记住了什么、依据是什么，以及如何纠正？这是一项产品设计目标，不能据此声称其他 AI 都没有记忆或本项目已经优于其他产品。

例如，**合成场景**：一名学生自述复习时常花太多时间整理资料。AI 提出带原话的候选，学生核对后确认，并设置目标「先做 20 分钟题，再查资料」。下一次讨论复习安排时，系统选择相关记忆和目标作为参考。这个例子说明流程，不证明用户已改变习惯或系统能够诊断人格。

项目在 2026 年 9 月 28 日调整为聊天优先。旧「普通 AI / Original Me / Better Me」三视角决策方案和相关页面保留为历史参考，不能继续当作正式软件主流程。

| AI 操作建议 | 聊天后提出目标、记忆归档和行动记录草稿；打开表单后仍需用户确认 | 自动执行的通用 Agent 或完整自动反馈闭环 |
| `/progress` 行动记录 | 用户记录选择、结果与自评，保留当时目标文本 | 自动测出改善程度或证明长期效果 |
| `/backup`、`/account` | 本地 JSON 备份恢复；可选邮箱账户与手动云端快照入口 | 日常资料已按云端账户完整隔离、实时同步或跨设备流程已全部验收 |

## Windows 运行与验证入口

首次获取项目需要 Node.js 24 及 npm，在项目根目录执行：

```powershell
npm.cmd ci
npm.cmd run dev -- --port 3001
```

打开终端显示的本地地址，主入口为 `/chat`。真实 AI 需要服务端 `LLM_API_KEY`；默认模型为 `deepseek-flash`。已有 `.env.local` 时直接核对所需项，不能用模板覆盖它；详细首次配置见 README。账户和语义实验分别有额外配置，核心本地聊天不要求先登录。

代码变更后的检查入口为 `npm.cmd test`、`npm.cmd run typecheck`、`npm.cmd run lint`、`npm.cmd run build`。模型、云端恢复和现场流程仍需分别实测，不能用自动测试或生产构建通过代替。
