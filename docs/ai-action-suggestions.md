# AI 操作建议（2026-10-11）

## 已实现的行为

在 `/chat` 成功得到并保存回复后，独立调用 `/api/chat/suggestions`，由现有 DeepSeek 模型检测本次意图。普通问题可以没有建议；检测失败显示错误，保留已保存的回复，并提供“重试操作建议”。旧回复尚未检测时可主动点击“检查操作建议”。

| 建议 | 打开时 | 确认后 |
| --- | --- | --- |
| 目标 | 在聊天中展开现有 `GoalEditor`，预填目标文字，可改文字与改变意愿 | 使用现有目标存储保存；同维度已有目标时先展示旧文字，按钮明确为“确认更新目标”，暂停状态保留 |
| 归档记忆 | 展示旧记忆依据和本次用户原话，核对是否仍适用 | 旧记忆归档，退出当前画像和聊天参考；依据及原始对话保留，可在我的画像重新确认启用 |
| 行动反馈 | 展开与 `/progress` 共用的 `OutcomeEditor`，预填实际行动及用户已明确报告的结果 | 用户补充结果、核对自评后写入现有行动记录，保存当时目标文本 |

点击卡片本身不改目标、记忆或行动记录。取消关闭表单；忽略只标记建议。完成和忽略状态会随聊天保留，刷新不会再次执行。归档操作不把这次新说法自动保存为已确认记忆；新记忆继续走原有提取与审核流程。

## 整体数据流程

1. 聊天请求照常选出相关的有效确认画像和启用目标，生成文字回复。
2. 回复保存后，把这次用户发言、刚生成的回复和同一批已选资料发送给建议检测接口。检测不额外读取全部历史资料，也不重新调用语义服务。
3. 模型输出 `suggestedGoal`、`suggestedArchive`、`suggestedOutcome`，每类最多一项。服务端校验维度、长度、本次连续原话及目标/记忆 ID，过滤无效项。返回最多三项草稿；浏览器再校验并绑定本次用户消息。
4. 草稿作为助手消息的可选 `suggestions` 字段保存。原 `zhiheng.chat.v1` 数据继续兼容；原本地和云端 JSON 快照包含建议，不建立第二套目标或画像结构。
5. 用户确认时，`actions.ts` 重新读取现有存储，检查建议是否仍待确认、旧来源是否有效、关联记录是否改变。目标编辑另外核对打开表单时的目标快照，防止静默覆盖后来修改。
6. 先通过现有 stores（存储模块）暂存业务改动和建议完成状态，再写入浏览器。写入失败会倒序恢复；如果恢复也失败，提示用户先核对和备份，避免重复确认。保存后刷新本页各模块缓存。

新增有限的“睡眠与作息”主题词，让“早起”的新说法可以召回“熬夜”的旧记忆；这只是相关资料检索，不能证明旧记忆已经过时。

## 运行与手工验收（Windows PowerShell）

使用现有 `.env.local` 的 `LLM_API_KEY`，默认模型仍为 `deepseek-flash`。首次获取项目才需要 `npm.cmd ci`；已安装依赖时直接运行：

```powershell
npm.cmd run dev -- --port 3001
```

打开终端显示的 `/chat` 页面，以下资料必须标为合成。模型输出具有不确定性，目标文字不要求与示例逐字相同。

1. **创建目标**：发“我最近总是拖延，想改掉这个习惯”。看到目标卡片后检查 `/profile` 尚未改变；打开草稿、修改文字后取消，仍不应保存。再次打开确认保存，到 `/profile` 核对；如果该维度已有目标，应先看到旧文字与更新提示。
2. **归档记忆**：在一段合成对话说“晚上经常熬夜到1点”，用原整理功能提取并核对确认这条记忆；再说“我现在已经习惯早起了”。卡片只提示可能需要更新。打开核对旧依据和新原话，确认归档后到 `/profile` 查看归档状态；原话仍在，不能自动出现新的确认画像。
3. **行动反馈**：先设置启用目标“每天先做20分钟复习题”，再说“今天我坚持复习了一小时”。打开行动卡片，动作已预填；未提到的结果应为空，需要补充并核对自评。确认后到 `/progress` 查看一条记录。刷新后建议应显示已处理，不能重复保存。
4. **无建议/否定/假设**：分别试普通 Python 问题、“今天没有复习”及“如果明天复习一小时”；不应把否定或未来假设记录为已完成行动。
5. **失败**：用浏览器 DevTools（开发者工具）的网络阻止功能单独阻止 `/api/chat/suggestions`，发送合成发言；聊天回复应保留、建议显示可重试。移除阻止后重试只检查建议，不重发聊天。
6. **记录变化**：打开确认表单后，在另一标签页修改关联目标或记忆，再返回确认，应拒绝旧操作并提示重新核对。暂停或删除目标后旧行动建议不可用。

自动验证命令：

```powershell

npm.cmd run typecheck
npm.cmd run lint
npm.cmd run build
```

## 限制与下一步

- 每次成功聊天多一次模型请求，有额外费用和等待时间；回复先显示，建议随后出现。没有额外配置开关。
- 检测仅针对本次发言和聊天已选资料。现有上限为最多五条画像、两项目标和 3000 字符附加资料；未被选中的记录无法建议归档或关联行动。关键词相关性可能漏选或误选，新增作息主题也不能替代完整语义判断。
- 模型的意图判断和建议文字仍可能不准确，必须人工确认。没有通用矛盾检测、后台学习或自动执行的 Agent。
- 业务资料仍在浏览器。云端快照包含建议的 JSON 兼容性已测试，真实账户跨设备恢复未因此视为验收完成。公开 production（生产）环境 AI 接口仍关闭。
- 后续可在有真实反馈后扩充否定、引用和复杂表达案例，评估检测成本；公开服务前仍需完成已有账户隔离与防滥用工作。

比赛材料可准确写：“AI 根据对话提出目标、记忆归档和行动记录建议，用户核对后确认执行。”本轮未修改比赛 PPT。
