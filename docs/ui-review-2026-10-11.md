# 知衡 UI 参考与优化建议

日期：2026 年 10 月 11 日。范围：现有桌面聊天空状态、参考资料展开、五项画像首页和问卷第一组。目的是确定优化顺序，本轮没有修改软件代码、安装组件或迁移开发环境。

## 结论

保留现有聊天优先结构，以及当前自评、用户目标、候选审核之间的区分。先统一白、黑、蓝视觉语言，再处理资料面板、画像切换和按钮反馈。无需另找完整聊天项目替换业务骨架。

“优先找开源”应落实为先核对可复用组件及其许可，再评估适配成本。当前项目使用普通 CSS，尚无 Tailwind、Motion 或 shadcn 配置；直接安装完整组件体系会增加依赖和样式改动。本阶段优先采用获许可的 CSS 过渡片段，复杂形变在具体模块确有需要时再评估 Motion。

## 检查步骤与证据

本轮截图保存于项目内已被 Git 忽略的 `output/ui-audit-2026-10-11/`，包含当前浏览器页面内容，只供本地检查，不上传为公共展示材料。以下文件在本轮保存后均已查看。

### 1 聊天空状态：入口清楚，视觉与新偏好不一致

![聊天空状态](../output/ui-audit-2026-10-11/01-chat.png)

优点：左侧主导航、开场示例、底部输入框层级清楚；待审核提示说明确认后才用于回答。这些结构适合保留。

观察：实际配色是米白、浅绿与深绿；导航没有 UI 图标，新对话和开场跳转仍使用文字符号。底部说明字号较小，输入框与开场区域之间留白较多。留白是否需要压缩取决于首屏布局目标，不是功能错误。

建议：先统一颜色 token（共享样式变量），采用白色表面、近黑文字、蓝色主要按钮和淡蓝选中态。为导航和操作采用同一套开源图标，保留文字名称。输入框获得焦点时增强边框；按钮 hover（悬停）轻微放大，按下时轻微缩小；不可用按钮保持明确的禁用外观。

实现时仍保留聊天列表、记忆审核和原有存储入口，不改模型或数据结构。空状态过渡到有消息时，可让开场区域退出、消息进入，保持输入框连续；本轮未发送消息验证该流程。

### 2 展开参考资料：内容可读，覆盖开场区域

![参考资料展开](../output/ui-audit-2026-10-11/02-reference-panel.png)

观察：面板从顶部右侧展开，覆盖了开场标题和部分示例区域。资料用途说明是清楚的，但展开前后的视觉联系较弱。代码使用 `details` 的开合状态，相关 CSS 未见统一进出动画。

建议：保持右上角按钮为视觉起点，面板从该位置扩展，内容在容器形成后淡入；关闭时反向收回。限制高度并允许内部滚动。先改善现有浮层，不在赛前直接把全页改成新的三栏布局。核对 Escape 关闭、焦点返回触发按钮及快速反复开合。

注意：单帧截图不能证明动画是否流畅；“缺少统一动画”结论同时依据当前 CSS 与开合实现，未做逐帧性能测量。

### 3 画像首页：信息分区合理，切换与空状态可改善

![画像首页](../output/ui-audit-2026-10-11/03-profile.png)

优点：五项具体行为置于顶部，当前自评和用户目标分成两块；未知状态没有被展示成低档。保留这种结构。

观察：空状态使用大面积浅绿块，信息较少；候选入口位于顶部右侧，页面下方另有待审核区域。代码通过 `hidden={!selected}` 切换画像内容，选中线也没有共享的移动过渡。

建议：选中下划线在五项标签之间滑动，外部容器保持稳定，旧内容退出后新内容轻微淡入。空状态减少无意义高度，用“当前还不了解这方面”与问卷、聊天入口说明下一步；目标区继续独立设置，不能因填写问卷自动创建目标。候选入口可加入清晰的数量 badge（数量标记），但不能单靠颜色表达待审核状态。

五项标签目前使用 `aria-pressed` 按钮，不能仅凭视觉像 Tabs 就断言它是无障碍错误。若后续改成标准 Tabs，应一起完成相应的键盘操作与语义，不只替换外观。

### 4 问卷第一组：语义清楚，首屏阅读负担偏高

![初始问卷第一组](../output/ui-audit-2026-10-11/04-questionnaire.png)

优点：提供进度、可跳过说明、不确定和没有相关经历选项，清楚说明确认保存后才用于相关回答；保留这些边界。

观察：在本次约 1280 × 720 桌面视口中，顶部说明与留白占据较多高度，第一题之后的内容以及下一组、跳过操作需要滚动才能看到。选项辅助说明字号较小。

建议：压缩顶部间距，提升选项说明可读性。维持每组三题，不贸然改成十五个单题步骤。选择时采用边框、背景与图标共同反馈；切组时固定进度区域，题组短距离过渡，并将键盘焦点引导到新组标题。研究让下一组和跳过更容易到达的操作条，必须检查不会遮挡选项。

## 动画规则建议

这些数字只是后续调试的起点，不是已经测出的最佳参数。

| 场景 | 建议起点 | 目的 |
| --- | --- | --- |
| 按钮悬停与按下 | 120–160 ms，约 1.02 / 0.98 的轻微缩放 | 点击反馈明确，保持文字可读 |
| 面板、菜单出现与关闭 | 180–240 ms，轻微位移、透明度和容器变化 | 看得出从哪里打开、向哪里收回 |
| 标签内容与布局变化 | 220–300 ms，短距离移动或淡入淡出 | 保持页面结构与对象连续 |

每个元素都应在对应生命周期中有出现、状态变化与消失的设计，可以随所属容器共同参与；避免让每个字、每条消息独立重复表演。共享侧栏可保持在场，内容区过渡。Morph 是保留对象身份并在多帧中连续变形，若全部变化只发生在一帧，就仍然是跳变。

实现退出动画时，不能在开始关闭的瞬间直接移除或隐藏元素；需保留到退出完成，并确保退出中的控件不会继续被操作。快速连续切换必须可打断，不能堆积动画。

系统开启减少动态效果时，缩减位移、缩放与形变，保留必要的状态提示。流式回答不能因动画反复移动阅读位置。短标题与按钮可省标点，长说明仍需清楚断句。
