# 我的背景、回答要求与记忆摘要

2026 年 10 月 11 日，安明确要求自由填写个人背景与回答要求，以及类似分类记忆摘要的展示。本轮在现有五项画像和记忆审核流程上增量接入，不新增依赖或第二套模型客户端。

## 现在分别保存什么

- **我的背景与回答要求**：用户主动填写的自由文字，包括学习/社会背景、当前项目、未来希望、表达偏好。它与画像候选分开，不自动创建正式目标。开启后，每次聊天附加这些设置；停用保留可编辑文字，清空只删除此处设置，已有聊天另行管理。
- **对话与问卷记忆**：已有功能，从聊天提取候选或通过问卷核对保存；仍只有用户确认且来源有效的记录才用于相关回答。可开启每四条新用户发言触发的候选整理，默认关闭；这不是后台学习。
- **记忆摘要**：按需把已确认记录按话题归纳，保留原记录引用；临时展示，不成为新事实，也不替代原记忆参与聊天。自由背景单独管理，不混入自动记忆摘要。

## 使用方式

1. 打开 `/profile#personal-context`，填写“希望 AI 了解的背景”和“希望 AI 怎么回答”，选择是否在聊天应用，点击保存。
2. 背景最多3000字，回答要求最多2000字。学校、专业、年级、社会关系和未来方向都可自由描述；未来希望仍是愿望，不会被写成已完成事实。
3. 到 `/chat` 提问；对话设置中的本次参考资料可查看实际附带的个人设置。明确中文“这次不要参考我的个人背景”可排除背景，自定义回答要求仍单独应用。
4. 在画像页展开“记忆摘要”，点击生成。最多读取最近20条有效确认记录，输入过长时只选可容纳的记录；界面显示本次数量，其他记录仍在原处。
5. 每段摘要的来源可展开，并定位到原记录修改、删除或归档。原记录变化后，旧摘要隐藏；编辑记忆后需重新确认，才继续参与聊天。

背景草稿在确认保存前只存在当前表单，离开或刷新会丢失；存储写入失败时保留草稿和旧存储值，能复制文字或直接重试。首次读取到损坏设置时不覆盖资料，提示从备份恢复。

## 数据、模型与备份契约

- `ResponsePreferenceState.personalContext?` 使用 enabled/background/instructions/updatedAt，仍存在 `zhiheng.response-preferences.v1`。快捷偏好与自由设置分别修改自己的字段，保留对方。
- 启用且有内容的设置进入聊天的 user JSON 附加资料，不插入新的 system 角色。回答要求优先于快捷偏好，但本次明确要求和系统边界优先；不通过自由文字增加联网、执行命令或发消息工具。
- 画像/目标/快捷偏好仍使用原3000字符选择预算；自由背景与回答要求分别限长，最终请求长度计入所有实际字段。
- 同一 `CloudSnapshot.preferences` 保存自由设置；旧快照可缺省。新设置损坏时先拒绝恢复，不改本地资料；依照现有逆序写入回滚规则。
- `/api/profile/summary` 复用现有 `requestModelCompletion`，仅本地开发开放，production关闭。最多4组简短描述，每段引用只能来自本次来源；没有配置、请求失败、JSON无效或引用无效时明确报错。
- 问卷日期保留；“最近四周”指填写日期之前四周，不把旧问卷一直视为当前状态。摘要是AI草稿，引用编号校验不能证明文字判断必然正确。
