# 知衡赛前记忆筛选实施计划

此文保留第一轮的设计与验证记录。第二轮改为保留完整所选原话，并新增独立本地恢复入口；当前安排以 `2026-10-07-local-recovery.md` 和路演准备文档为准。

> 按已确认的聊天方案，使用 executing-plans 在当前会话中逐项实施。保留当前功能分支上的既有未提交代码；不自动提交、推送、合并或部署。

**目标：**排除无关记忆、选择相关目标、限制上下文，并展示实际请求的参考资料。

**架构：**保留本地存储和现有 API。规则匹配负责召回，聊天上下文模块负责语境与预算；界面展示同一次选择结果，不重新计算已经发送的请求。

**技术：**现有 Next.js、React、TypeScript、Node 内置测试，不增加依赖。

**设计依据：**本聊天中用户已确认的赛前 MVP 方案，以及 `docs/product-vision.md`。

## 约束与决定

- 候选、驳回和失效来源不进入长期参考；目标独立保存。
- 最多 5 条画像、2 项目标；模型实际附加资料 JSON 最多 3,000 字符。
- 仅明确追问借用最近用户语境；话题切换不沿用旧主题。
- 展示的是请求参考资料，不声称模型一定采纳；失败也标明状态。
- 采用规则与有限主题词，不称语义向量检索；不增加心理测评。
- 保留旧浏览器数据格式，参考资料展示仅属于本页请求记录。
- Ruling：在当前 feature 分支修改，避免新 worktree 丢失本地新增模块；代价是最终整合必须区分已有修改与本轮文件。
