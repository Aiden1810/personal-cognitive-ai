# 画像如何影响回答：最小改动

用户希望改变画像后，AI 的回答方式、建议方法和帮助程度随之改变。保留已有七维画像、候选审核、来源校验、检索和目标模块，只给每条记忆增加一个可选字段 `responseAdaptation`。

## 行为

| 等级 | 给模型的要求 |
| --- | --- |
| 低 / low | 根据具体记录调整用词与限制，通常两三个要点，不主动展开完整教程 |
| 中 / medium | 根据记录选择适合的方法，按需补一个例子或几个步骤 |
| 高 / high | 优先选一种适合的方法，说明理由，给起步步骤、卡点与可观察的检查标准 |

这是用户对帮助程度的选择，不是人格强弱、能力测量、事实置信度或目标改变意愿。具体难度与方法仍根据画像的文字内容决定，不能从七维名称猜测更多特点。

当次明确要求优先于全局回答偏好，全局回答偏好优先于画像适配。高档也需遵守“只用一句话”等要求；多条记录分别影响相关方面，不能因为一条高档就让所有问题变长。当前明确状态优先于历史状态。

## 数据和请求

- `ProfileInsight` 可选字段，取值只接受 `low`、`medium`、`high`。旧记录无需重写，展示和序列化默认使用中档。
- 修改等级不改变 `statement`、`evidence`、`origin`、`scope` 或审核状态。修改画像文字仍沿用已有重新审核流程。
- 沿用已有筛选条件：已确认、来源有效、与问题相关。等级不提升检索得分，不使候选、归档或无关记录进入回答。
- 序列化与服务端校验都计入现有 3,000 字符附加资料预算。等级进入实际模型请求，系统提示解释其含义。
- 本地 JSON 与手动云端快照沿用 `ProfileState`，字段自然保留，无数据库迁移。本轮只验证本地导出与恢复，不宣称云端专项验收完成。
- `/profile` 和 `/chat` 的已确认画像提供折叠选择框，选择后即保存。聊天参考面板展示请求快照里的等级；后续改动只影响下一次请求。

## 自己验证

1. 在 `/profile` 找到一条已确认且原话有效的画像，展开“回答适配程度”，选择低。
2. 新建聊天，提问一个与该画像相关的问题，展开“本次请求的参考资料”核对画像和低档。
3. 回画像改成高，刷新确认保存，再新建聊天问同样的问题，核对高档和回复。
4. 用无关问题、明确不参考画像的问题，以及“只用一句话”的问题检查边界。

本轮没有新增自动人格评分、自动确认、长期记忆冲突处理或更精准的检索算法。等级通过模型提示影响回答，不能保证每次输出满足所有风格要求；现有关键词与实验语义检索的漏选、误选仍可能影响画像是否参与。
