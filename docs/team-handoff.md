## 当前可检查的部分

安负责的 `/chat` 技术占位页已接入本地开发用的 `/api/chat` 接口。没有配置 API Key 时会显示错误，保留用户消息并提供重试；2026 年 9 月 28 日已用 `deepseek-flash` 完成一条真实短消息连通测试。现在可手动调用 `/api/profile/extract`，从当前对话的用户消息提出最多 3 条带原话的候选；用户也可主动开启“持续整理”，之后每新增 4 条用户发言，在 AI 成功回复后自动运行同一候选接口。候选仍需审核，使用 `src/lib/profile` 统一保存。`/profile` 以五项行为为主、保留其他背景，已确认且来源仍有效的洞察才参与聊天。仍无云端同步；测试请使用虚构文字。旧演示页面仍在，作为之前方案记录。

安已用虚构复习案例实际排练「聊天 → 提取与审核 → 设置目标 → 新对话」闭环。比赛演示顺序、PPT 页面建议与能力边界见[演示交接](contest-demo-handoff.md)；案例可替换，不应写成正式产品场景。

## 已固定的公共契约

- `src/types/cognitive.ts`：`TraitDimension` 为五项行为；`CognitiveDimension` 兼容五项与旧七维。`ProfileInsight` 含来源、审核状态、可选当前档位，证据区分问卷与聊天；`UserGoal` 独立保存目标及可选目标档位，不覆盖当前洞察。`ProfileConflict` 保留为历史类型，不代表自动矛盾检测已验收。
- `src/lib/ai/chat.ts`：`ChatRequest` 含 `messages`、`insights`、`goals`。服务端仅把 `confirmed` 洞察和 `active` 目标送给模型；候选和已驳回洞察不得参与个性化回复。最后一条消息须为用户消息。
- `src/lib/profile/context.ts`：最多选择 5 条相关已确认画像，零匹配不补满；`relevance.ts` 使用词项与有限主题词，仍是规则检索。提取范围保持最近最多 20 条用户发言、合计 2 万字符，并返回遗漏条数。
- `src/lib/chat/context.ts`：明确追问使用最近用户语境，最多 2 项相关启用目标；画像描述决定相关性，每条最多两段完整原话，每段沿用存储的 500 字符上限；模型附加资料 JSON 不超过 3,000 字符。明确中文“不参考画像”请求会排除本次长期画像，目标仍独立选择。`serializeChatContext` 用于预算及模型请求，服务端拒绝超限；API 第五参数回调返回同一次选择。来源有效性仍由浏览器入口 `usableProfileInsights` 验证，尚无公开服务账户事实校验。
- `/backup` 与 `src/lib/backup`：独立本地备份入口，不引用云端 SDK、不经过账户会话刷新。本地 JSON 最多 5 MB（UTF-8 字节），先校验、显示数量、再主动恢复。沿用版本 1 格式，在同一次写入中关闭自动提取并清除旧检查点；写入失败倒序回滚，避免旧大对话和新大画像叠加超出容量。
- `POST /api/profile/extract` 可附加 `existingInsights`（最多 30 条 `{ dimension, statement, status }`），客户端从本次原话相关的已有记录选取。它们只用于避免重复，不可作为新候选的证据；所有候选仍须引用本次用户原话。字段可省略，以兼容已有调用。姚的审核组件应复用此范围计算，不自行按助手消息截断。
- `src/lib/profile/auto.ts`：自动提取默认关闭；用户开启时记录当前各对话的最后一条用户消息，从此每新增 4 条触发一次。检查点只用于避免重复请求；关闭开关后不再触发。模型失败或保存失败要展示错误，不能把候选自动确认为事实。
- `POST /api/profile/reflect`：只在用户点击后调用，输入 `insights` 最多 20 条 `{ id, dimension, statement, quotes }`；由 `/profile` 从已确认且来源有效的洞察及原话摘录构造。服务端固定使用 DeepSeek Flash；输出 `reflection` 含 `strengths`、`growthAreas`、`tensions`，每项都有 `text` 和 `insightIds`。张力须引用两条不同洞察，未知引用会被过滤。结果只在当前页面暂存，不写入画像或聊天上下文。
- `src/lib/goals`：每个七维分类最多一个用户填写的目标，状态为 `active` 或 `paused`；目标与当前画像分开保存。聊天只发送启用且相关的目标，页面不得将目标描述成已发生的事实。
- `UserGoal.willingness` 为可选字段，允许 `not_now`、`slight`、`moderate`、`strong`、`highest` 五档，标签与说明统一在 `src/lib/goals/willingness.ts`。它表示用户自评的改变意愿，旧记录省略该字段。`upsert` 第三个参数省略时保留原值，传 `null` 清除选择；编辑不自动启用已暂停目标。聊天服务校验等级，只发送启用目标的文字含义，不发送百分比。云端快照保留此字段；正规化 `goals` 表通过 `add_goal_willingness` 迁移增加可空字段。
- `POST /api/chat` 接收上述 JSON，成功返回 `{ "ok": true, "data": { "reply": "模型文字" } }`；失败返回 `{ "ok": false, "error": { "code": "...", "message": "..." } }`。本地缺少 `LLM_API_KEY` 返回错误，不生成示例答案。接口在 production 暂关闭，直到账户隔离和防滥用措施完成。
- 安已建立专用 Supabase 项目与十张启用 RLS 的表，结构见 `database/schema.sql`。`/account` 提供登录和用户主动触发的云端资料快照；消息、画像等业务模块仍以当前浏览器为工作副本，尚未逐条实时同步。姚、曹不要自行创建表、迁移或第二套数据入口，也不要把自动提取的候选当作已确认画像。
- `src/features/profile/profile-review-panel.tsx` 是安为验证数据闭环做的简易审核区。曹可以重新设计正式 UI；姚可基于公共类型与 `src/lib/profile` 继续改善来源核对，公共契约变动由安统一合并。
