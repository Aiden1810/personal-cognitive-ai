# Personal Cognitive AI

一个根据历史决策提出行为模式、由用户确认改进目标，并在类似决策中提供有证据、可追溯建议的个人 AI 项目。

**状态：项目启动与文档阶段。尚未实现应用，也没有可运行的 Demo。**

大学创新比赛项目，团队共 3 人。项目名称暂定；具体演示场景待团队确定。

## 1. 项目目标

核心流程：

**历史决策 → 候选行为模式 → 用户确认 → 用户自主设定目标 → 新决策中的辅助建议 → 实际选择与结果记录。**

系统把两件事分开：

- 根据过去的记录，用户可能怎样选择；
- 根据用户现在设定的目标，系统可以怎样帮助。

AI 提出候选观察，用户决定观察是否成立，以及是否希望改变。系统不做心理诊断、不测量人格，也不声称原型已证明长期认知改善。

## 2. 三种结果

| 视角 | 使用的信息 | 输出性质 |
| --- | --- | --- |
| 普通 AI | 当前问题、备选项和约束 | 通用建议 |
| Original Me | 当前问题、历史案例和已确认模式 | 历史行为倾向预测，不是行动推荐 |
| Better Me | 当前问题、历史证据、用户主动启用的目标及适用规则 | 目标导向建议，最终由用户决定 |

三者使用相同的基础模型、当前问题和生成设置，但分别构建请求上下文。普通 AI 不接收个人历史或改进目标。系统不强制三种结果得出不同结论。

## 3. 首版范围

提交前只做一个场景的一条完整流程。场景待定，确定后由团队统一准备案例与验收问题，不在基础模块中写死特定故事。

### 必须包含

1. 查看、添加、编辑和删除历史决策案例。
2. 提出候选行为模式，展示支持案例、反例及信息不足。
3. 用户确认、修改或驳回模式；仅已确认模式进入个性化生成。
4. 用户选择是否改变，并设置、修改或停用一条具体目标。
5. 输入新的问题与约束，展示三种结果及依据。
6. 记录实际选择；允许之后补充结果。

证据查看嵌入模式和回答界面；反馈记录嵌入决策页面，不为每个动作新增页面。

### 提交前暂缓

- 正式注册登录、云端多用户数据库。
- 多种认知模式、完整七层人格模型、0–100 特质评分。
- 任意聊天记录自动导入、自动裁决矛盾。
- 本地大模型训练、Second Me Fork、Personal AI 接入。
- 向量检索、复杂多代理、预测准确率看板。

## 4. 产品流程与页面

1. 进入明确标识的演示身份。
2. 查看或录入案例，检查来源和实际选择。
3. 请求分析，核对候选模式的证据，确认、修改或驳回。
4. 用户自主决定是否改变，并启用具体目标。
5. 输入新的决策问题和必要背景。
6. 查看普通 AI、Original Me、Better Me，以及引用的案例和目标。
7. 记录自己的实际选择，之后补充结果。

计划页面：

- `/history`：历史案例与模式审核。
- `/goals`：目标设置。
- `/decision`：新问题、三视角、证据和反馈。

路由是开发约定，当前尚未实现。

## 5. 推荐架构

| 部分 | 提交前原型 | 提交后 MVP |
| --- | --- | --- |
| 页面 | Next.js、React、TypeScript | 保持 |
| 服务端 | Next.js 服务端接口 | 保持 |
| 生成 | 统一服务端 LLM API Adapter，供应商和模型待确定 | 根据实测效果调整 |
| 数据 | 预置演示数据与浏览器本地保存，通过统一数据入口访问 | Supabase / PostgreSQL |
| 用户身份 | 演示身份 | Supabase Auth 与按用户隔离 |
| 证据检索 | 按场景、确认状态与案例编号筛选 | 出现实际检索问题后再评估 pgvector |

浏览器保存不等于云端账户：不跨设备同步，清除浏览器数据可能丢失记录。首版仅使用合成或脱敏演示资料；服务端仅处理生成请求，不把浏览器资料自动视为可信事实。

核心系统层负责数据、确认状态、目标、规则、引用检查和反馈。LLM 负责候选提取与语言表达，不自动宣布心理问题或替用户定义什么是 Better。

## 10. 最小 Demo 验收

- [ ] 场景已确定，案例来源标明；合成资料显示为演示数据。
- [ ] 可查看约 5 个案例，包含一个反例。
- [ ] 一个模式可确认、修改、驳回；确认不自动启用改进目标。
- [ ] 一条用户目标可启用和停用。
- [ ] 一个新问题产生三种结果，标明预测与建议的区别。
- [ ] 可以查看实际引用的案例和目标，引用没有凭空生成。
- [ ] 证据不足时明确说明；请求失败不会假装生成成功。
- [ ] 可以保存实际选择，并在刷新后查看。
- [ ] 能明确区分真实生成和预置示例。

## 11. 提交后

1. 接入正式身份与云端保存，落实用户数据隔离、编辑和删除。
2. 完善模式审核、目标停用和历史生成依据保存。
3. 小规模试用，记录判断错误、录入负担和建议可执行性。
4. 根据试用问题决定是否扩展第二个场景或检索能力。

用户采纳建议不等于建议正确；一次演示不等于已证明认知改善。
